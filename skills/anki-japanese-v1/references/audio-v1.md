# 音频配置与执行

公开版建议用两个独立配置：单词使用 GPT-SoVITS `v5dev` 标准版，例句使用 `v2ProPlus`。用户可以提供其他兼容音色或模型；确认具体声音后，应保留权重、参考录音和逐字参考文本的身份及生成参数。仓库不附权重或声音。初次换声音先制作少量样卡试听。

配置格式见 [v1.profile.example.json](../assets/v1.profile.example.json)。从配置文件所在目录解析仓库、参考音频及运行模块，权重从各自上游仓库目录解析；复制配置后重新核对路径。参考录音与文本须匹配，微调模型一般也需要参考录音。完整模型安装与服务说明见仓库的 `docs/setup-tts.md`。

历史运行在 Intel Arc A750 上使用 FP32，随机种子 `20261102`、语速 `1.0`、最长分段 150 字符；V5 使用 32 步及 CFG 1.3，输出 48 kHz；V2ProPlus 输出 32 kHz。这是参考配置，不保证其他设备或模型有相同表现。V5 声码器和 V2ProPlus 说话人编码器等组件由上游模型环境提供。

单词和例句均优先验证并使用真正批量推理：当前适配器 V2Pro/Plus 支持最多 4 条，V5 当前回退单条；并发调用普通 `/tts` 只会排队。先检查批次中每段音频的内容、顺序、声音与显存占用。单条过长或落单时回退逐条。更换模型或批量实现后重新验证。

同一阶段模型在 GPU 上常驻，重复利用参考特征；显存不足时按模型分阶段运行，不在同一进程切换两个上游仓库。文本、权重、参考、参数变化时必须生成新配置身份。相同种子在串行和批量路径下不保证字节一致。

展示文本与实际朗读不同的情况使用 `tts_word_text` 或 `examples[].tts_text` 保存实际输入与理由。缩写、多音词和人名需要先确认读法；文本前端检查及音频文件检查都不能证明实际音调正确。
