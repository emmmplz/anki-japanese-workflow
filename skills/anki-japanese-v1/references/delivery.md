# 导出、验证与交付

## 词包

导出前把所有音频引用解析为实际文件。每个单词有对应的 V5 音频；每条日语例句有对应的已配置音频。相同文本且配置一致的例句可以共享文件，但不能因此省略卡片上的播放器或混淆译文对应关系。

媒体文件使用稳定、跨平台可用的名称。Anki 字段使用 `[sound:文件名.wav]`，`.apkg` 中包含这些文件；试听页面使用与媒体目录一致的相对路径，打开或解压后可以离线播放。

沿用旧词包时保留原字段及其顺序、模型 ID 和 GUID。背面在原词语与例句字段嵌入音频；导出器末尾追加两个派生字段 `正面单词`、`正面用例`，只含不带声音和译文的正面内容。正面模板只引用这两个字段，不通过隐藏播放器实现静音；`text:` 过滤 HTML 也不会阻止 Anki 提取声音。新增字段是正背面隔离所需，不改变原有字段位置。生成新 `.apkg`，保留旧包，并验证旧包更新后的身份和调度；具体接口见 [running.md](running.md)。

## 有意义的验证

- 核对源条目、合并笔记、生成卡片和音频覆盖数；每个计数单独报告。
- 扫描全部 `[sound:...]`，验证媒体文件存在、没有错误地指向另一模型的输出，包内媒体表与文件能一一对应。
- 读取每个 WAV 的格式与内容统计，并核对清单摘要；不要只凭文件扩展名或 HTTP 200 判定成功。
- 检查每张笔记的原有 ID、GUID、课次、词义、例句和译文是否保留；校订警告仍可见。
- 解析导出的 Anki 数据，核对笔记、卡片、模型、字段与媒体数量。可用本地 Anki 导入库时，在隔离临时收藏中实际导入验证，不污染用户正在使用的收藏。
- 预览正面无播放器、声音引用或中文译文，背面单词及每条例句均可播放；原生 Anki 渲染须检查全部卡片的 question AV 队列为空，answer AV 队列与清单逐项匹配。长例句和音调标注在窄屏不溢出。可用浏览器自动化时检查实际渲染；不可用时明确记录结构检查范围，不虚称完成视觉检查。

已试听确认的样卡可以作为检查基线，但只有实际输入和全部生成配置匹配时才作为批次缓存。文件检查不是逐条人工听审；交付记录应分别说明结构检查、音频检查和听审范围。

排版验证同时检查：背面模板没有“原表声调”段落，假名音调标注仍在；词性与中文释义使用同一行、同字体、同字号和同字重。原始声调字段不删除，旧模板再次导出时也应用当前排版约定。

补音频的隔离导入验证应先导入旧包，再导入新包，核对全部笔记/卡片身份及重复数；复习状态若只检查代表卡，报告必须明确是抽样。局部校订后重新导出并重验引用，交付媒体目录按最终清单整理，旧而未使用的音频移到备份记录，不混入最终媒体集合。长开头静音或极短有效发声的处理边界见 [试运行复盘与执行建议](operations-review.md#质量检查与交付边界)。

## 交付结构

通常交付一个带音频的 `.apkg`、一个可搜索并播放的 HTML 预览，以及简短的运行报告。保留可供续跑的规范化笔记、音频清单、配置快照、校订记录与需要附带的数据许可。原始模型音频可与制卡音频分开保存。

报告写明实际完成的笔记/卡片数、单词与例句音频覆盖、去重数量、未解决的内容警告、所用 v1.0 配置和检查结果。存在缺失音频时不能标成“全部补齐”；给出具体缺失项并继续处理。

将流程安装为技能时，技能包只收录本身运行需要的脚本、模板、轻量推理适配器、说明和小配置示例。推理权重、参考录音、完整训练数据、虚拟环境、模型下载缓存以及本次整批生成音频都留在项目输出或外部模型目录。个人本地配置负责把技能连接到这些资源。

除非用户同时要求导入、同步或修改实库，交付 `.apkg` 即完成词包导出，不自动更新正在使用的 Anki 收藏。
