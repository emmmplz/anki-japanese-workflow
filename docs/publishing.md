# 上传前检查

1. 打开 README 和三个示例，按实际情况调整项目名称、作者与版权归属；当前 MIT 许可使用 `Anki Japanese Workflow contributors` 作为版权声明。确认有权按此许可证发布仓库内容。
2. 确认仅上传此目录。检查本地配置、日志和历史提交没有真实姓名、绝对路径、密钥、参考录音、模型权重、教材、个人词包或未经授权的素材。`.gitignore` 不会清除已经提交到历史中的文件。
3. 查看 README 中的[第三方项目和资源](../README.md#第三方项目和资源)以及模型、声音、依赖和数据各自的许可证；代码许可不等于声音或数据许可。
4. 本目录执行 `python tools/check_release.py`，并执行 README 所列的测试。实际的上游模型与 GPU 推理须在自己的授权环境中另行验证。
5. 在此目录单独初始化 Git 仓库，检查 `git status` 和待提交差异；由发布者创建 GitHub 仓库并推送。不要从上层工作目录整体上传。

示例 `.apkg` 作为 GitHub Release 附件上传，不放入源码目录或 Git 提交。README 的示例链接指向对应 Release 页面。

`.zip` 仅作为方便传输的快照，后续修改以目录内容为准。发布前仍应人工复核。
